## ۱. هدف سرویس

سرویس `area-doors` برای این طراحی شده که:

1. با گرفتن **مختصات کاربر** (lon/lat) و **شماره طبقه**، محدوده‌ی متقاطع (مثلاً صحن، حیاط، فضای بزرگ) را پیدا کند.
2. اگر مساحت محدوده حداقل **۱۰۰۰ متر مربع** باشد:

   * خودِ محدوده را به صورت **GeoJSON** (برای هایلایت روی نقشه) برگرداند.
   * لیست درب‌های متصل به آن محدوده را از جدول `door_access_points` جمع کند.
   * درب‌ها را به صورت **ساعت‌گرد از جهت شمال‌غرب محدوده** شماره‌گذاری کند (doorNo = 1, 2, 3, …).
   * برای هر درب یک متن توضیحی مثل
     `درب شماره 3 از صحن انقلاب به صحن گوهرشاد`
     تولید کند.
3. اگر مساحت محدوده کمتر از ۱۰۰۰ متر مربع باشد، پیام خطای معن‌دار برگرداند (برای این نوع سرویس در نظر گرفته نمی‌شود).

این سرویس به‌صورت مستقیم برای **هایلایت محدوده روی نقشه** و نشان دادن **درب‌های آن محدوده با شماره‌ی یکتا و متن قابل فهم برای کاربر** استفاده می‌شود.

---

## ۲. Endpoint و روش فراخوانی

* **URL:**
  `GET /api/v1/area-doors`

* **Method:**
  `GET` (در صورت نیاز می‌توان به `POST` هم تغییر داد، فعلاً روی GET تنظیم است.)

### پارامترهای ورودی (Query String)

| پارامتر | نوع     | اجباری | توضیح                                                          |
| ------- | ------- | ------ | -------------------------------------------------------------- |
| `lat`   | number  | ✔️     | عرض جغرافیایی کاربر (WGS84 – EPSG:4326)                        |
| `lon`   | number  | ✔️     | طول جغرافیایی کاربر (WGS84 – EPSG:4326)                        |
| `floor` | integer | ✔️     | شماره طبقه (مثلاً 0 برای همکف، 1، 2، …)                        |
| `lang`  | string  | ✖️     | کد زبان برای متون (مثلاً `fa`, `en`, `ar`, `ur`)، پیش‌فرض `fa` |

نمونه درخواست:

```http
GET /api/v1/area-doors?lat=36.2879&lon=59.6163&floor=0&lang=fa
```

## ۳. ساختار پاسخ‌ها

### ۳.۱. پاسخ موفق (status = "ok")

وقتی محدوده‌ای پیدا شده، مساحت آن بالای ۱۰۰۰ متر مربع است و درب‌هایی به آن متصل شده‌اند:

```json
{
  "status": "ok",
  "data": {
    "area": {
      "id": 1234,
      "name": "صحن انقلاب",
      "floor": 0,
      "areaM2": 3500.42,
      "coord32640": [734900.1, 4018800.2],
      "coord4326": [59.6163, 36.2879],
      "bbox4326": [59.6158, 36.2875, 59.6168, 36.2883],
      "geometry": {
        "type": "Polygon",
        "coordinates": [
          [
            [59.6159, 36.2876],
            [59.6167, 36.2876],
            [59.6167, 36.2882],
            [59.6159, 36.2882],
            [59.6159, 36.2876]
          ]
        ]
      }
    },
    "doors": [
      {
        "doorNo": 1,
        "doorId": 567,
        "accessId": 890,
        "label": "درب شماره 1 از صحن انقلاب به صحن گوهرشاد",
        "fromAreaId": 1234,
        "fromAreaName": "صحن انقلاب",
        "toAreaId": 2233,
        "toAreaName": "صحن گوهرشاد",
        "otherAreaId": 2233,
        "otherAreaName": "صحن گوهرشاد",
        "coord32640": [734905.3, 4018810.4],
        "coord4326": [59.6165, 36.2881]
      }
      // ... درب‌های دیگر
    ]
  }
}
```

#### توضیح فیلدهای مهم برای فرانت:

**data.area**

* `id`: شناسه محدوده در دیتابیس.
* `name`: نام محدوده به زبان درخواستی (مثلاً «صحن انقلاب»).
* `floor`: شماره طبقه.
* `areaM2`: مساحت محدوده بر حسب متر مربع (برای کنترل یا نمایش در UI).
* `coord32640`: مرکز هندسی محدوده در سیستم مختصات داخلی (برای GIS داخلی).
* `coord4326`: مرکز هندسی محدوده در WGS84 (برای فوکوس روی نقشه).
* `bbox4326`: باکس محدودکننده‌ی محدوده در WGS84 (`[minLon, minLat, maxLon, maxLat]`).
* `geometry`: خود هندسه‌ی محدوده به صورت **GeoJSON 4326**؛ مستقیماً قابل استفاده در کتابخانه‌های نقشه مثل MapLibre/Mapbox.

**data.doors[]**

هر عنصر یک درب در `door_access_points` است که به این محدوده وصل شده:

* `doorNo`: شماره‌ی یکتای درب در چارچوب همین محدوده، شماره‌گذاری شده **ساعت‌گرد از شمال‌غرب محدوده**.
* `doorId`: شناسه‌ی درب (entity اصلی door) – اگر لازم شد برای لینک به جزئیات بیشتر.
* `accessId`: شناسه‌ی رکورد در `door_access_points` (نقطه‌ی عبور).
* `label`: متن نهایی برای نمایش به کاربر، مثل:
  `درب شماره 3 از صحن انقلاب به صحن گوهرشاد`
* `fromAreaId`, `fromAreaName`: محدوده‌ای که درب از آن شروع می‌شود.
* `toAreaId`, `toAreaName`: محدوده‌ای که درب به آن می‌رسد.
* `otherAreaId`, `otherAreaName`: «محدوده‌ی طرف مقابل» نسبت به محدوده‌ی انتخاب‌شده (برای توضیح مقصد).
* `coord32640`: مختصات نقطه‌ی درب در سیستم مختصات داخلی.
* `coord4326`: مختصات نقطه‌ی درب در WGS84 – همین را برای نمایش marker روی نقشه استفاده کنید.

### ۳.۲. محدوده‌ای پیدا نشد / دربی متصل ندارد (404)

اگر برای مختصات داده‌شده هیچ محدوده‌ای پیدا نشود یا محدوده‌ای که پیدا شده هیچ درب متصلی نداشته باشد:

```json
{
  "status": "not_found",
  "message": "هیچ محدوده‌ای برای این مختصات یافت نشد یا دربی متصل ندارد."
}
```

در این حالت فرانت می‌تواند:

* پیام دوستانه به کاربر نمایش بدهد،
* یا اصلاً چیزی روی نقشه هایلایت نکند.

---

### ۳.۳. مساحت محدوده خیلی کوچک است (400)

اگر محدوده پیدا شود، ولی `areaM2 < 1000` باشد:

```json
{
  "status": "area_too_small",
  "message": "مساحت محدودهٔ انتخابی کمتر از ۱۰۰۰ متر مربع است و برای این سرویس در نظر گرفته نمی‌شود.",
  "data": {
    "area": {
      "id": 999,
      "name": "راهرو طبقه همکف",
      "floor": 0,
      "areaM2": 120.5,
      "coord32640": [...],
      "coord4326": [...],
      "bbox4326": [...],
      "geometry": { ... }
    }
  }
}
```

> نکته: با این‌که خطا است، `data.area` را برمی‌گردانیم تا اگر فرانت خواست، بتواند همان محدوده کوچک را *کم‌رنگ‌تر* یا *با استایل متفاوت* نشان دهد، ولی در UI مثلاً بنویسد «این محدوده برای لیست درب‌ها در نظر گرفته نمی‌شود».

---

### ۳.۴. خطای اعتبارسنجی (422 – Validation)

اگر پارامترهای ورودی ناقص یا نامعتبر باشند (مثلاً `lat` خالی باشد)،
ساختار استاندارد Laravel Validation برگردانده می‌شود (JSON با لیست خطاها).
فرانت بهتر است این را به صورت کلی هندل کند.

---

### ۳.۵. خطای داخلی (500)

اگر ساختار غیرمنتظره‌ای از سمت دیتابیس برگردد، سرویس:

```json
{
  "status": "error",
  "message": "ساختار داده دریافتی از پایگاه داده نامعتبر است."
}
```

برمی‌گرداند.
این حالت نادر است و در حالت عادی نباید رخ دهد.

## ۴. سناریوی پیشنهادی استفاده در فرانت

### ۴.۱. سناریوی اصلی (User Tap روی نقشه)

1. کاربر روی نقشه (MapLibre/Mapbox) روی یک نقطه کلیک/تاچ می‌کند.

2. فرانت lon/lat آن نقطه را می‌گیرد.

3. با `floor` فعلی (از UI یا state) و `lang` فعلی اپ، درخواست زیر را می‌فرستد:

   ```js
   GET /api/v1/area-doors?lat=<lat>&lon=<lon>&floor=<floor>&lang=<lang>
   ```

4. بر اساس `status`:

   * اگر `status === "ok"`:

     * لایه‌ی **polygon** جدید با استفاده از `data.area.geometry` (GeoJSON) روی نقشه اضافه کند با رنگ/استایل برجسته‌تر (هایلایت محدوده).
     * فوکوس/زوم نقشه را اگر لازم است روی `data.area.coord4326` تنظیم کند.
     * برای هر عنصر در `data.doors` یک **marker** یا **symbol layer** در مختصات `coord4326` اضافه کند.
     * روی marker می‌تواند از `doorNo` یا `label` به عنوان text استفاده کند.
     * همچنین در یک پنل کناری/پایین، لیست درب‌ها را مرتب بر اساس `doorNo` نشان دهد.

   * اگر `status === "area_too_small"`:

     * می‌تواند محدوده را با رنگ کم‌رنگ‌تر (مثلاً خاکستری) ترسیم کند (از `data.area.geometry`).
     * پیام مناسب به کاربر نشان دهد که «این محدوده خیلی کوچک است و لیست درب‌ها برای آن فعال نیست.»

   * اگر `status === "not_found"`:

     * پیام «در این نقطه محدوده‌ای یافت نشد» یا مشابه آن را به کاربر نمایش دهد.
     * لایه‌های قبلی در صورت نیاز پاک شوند.

   * اگر `status === "error"` یا خطای ۵۰۰ یا ۴۰۴/۵۰۰ دیگری:

     * پیام خطای کلی «مشکلی در سرویس رخ داده است، لطفاً دوباره تلاش کنید.» نمایش داده شود.

## ۵. خلاصه برای تیم فرانت

* **Endpoint:**
  `GET /api/v1/area-doors?lat=...&lon=...&floor=...&lang=...`

* **کارکرد:**
  گرفتن محدوده‌ی بزرگ اطراف کاربر (مساحت ≥ ۱۰۰۰m²)،
  برگرداندن هندسه‌ی GeoJSON برای هایلایت،
  و لیست درب‌های متصل به آن محدوده به صورت شماره‌گذاری‌شده از شمال‌غرب به صورت ساعت‌گرد.

* **کلید اصلی برای نقشه:**

  * `data.area.geometry` → polygon برای رسم روی نقشه
  * `data.area.coord4326` → مرکز محدوده (برای فوکوس/زوم)
  * `data.doors[*].coord4326` → نقاط درب‌ها (marker)
  * `data.doors[*].doorNo` و `data.doors[*].label` → متن لیبل و لیست
